# CI 자동 검증

상태: Completed
종료일: 2026-10-30

## Purpose / Big Picture

PR과 master·codex 브랜치 push마다 포맷·정적 분석·빌드·테스트를 자동 검증한다. 일반 로직/미지원 처리와 macOS/APFS 저장·복구 검증을 나누고, 필수 테스트 누락·skip·잘린 결과를 성공으로 처리하지 않는다. 전원 장애 검증은 사용자가 보류했으며 CI 완료 조건에서 제외한다. 기존 v1 계획의 미검증 사실은 유지한다.

## Surprises & Discoveries

- 기존 setup은 macOS arm64 전용이다. CI는 setup-go로 .go-version의 정확한 버전을 설치하고 기존 wrapper의 .tools 경로에 연결한다. 로컬 설치 규칙과 Go 버전을 변경하지 않는다.
- native 테스트는 darwin/cgo build tag를 사용한다. cgo=0에서 성공해도 저장 검증을 실행한 증거가 아니다.
- snapshot의 TestSnapshotPublisherChild는 부모 시험에서 실행하는 helper이므로 일반 수집의 skip을 명시적으로 허용한다. 실제 부모 프로세스 장애 시험은 반드시 실행한다.
- 최초 native 사전 검사의 shell stat 형식은 파일 시스템 종류를 반환하지 않아 실패했다. 이를 제거하고 storageprobe가 기존 durable.CheckFilesystem을 호출하게 해 WAL과 같은 APFS 판별을 사용한다. 수정 뒤 전체 native 검사와 cgo=0 probe 테스트가 통과했다.

## Outcomes & Retrospective

CI 구현과 로컬 검증을 완료했다. 일반/실제 저장 두 job, exact Go와 Actions SHA, 제한 시간·동시 실행 제어·진단 artifact, 누락/skip 검증을 추가했다. 거래 API·저장 형식·production dependency는 변경하지 않았다.

이 계획의 최초 로컬 구현 완료 시점에는 GitHub-hosted runner에서의 실제 실행과 branch protection은 미검증·미설정이었다. 초기 구현 요청에는 master 병합·push가 포함되지 않았다. 아래 portable의 로컬 실행은 macOS/cgo=0이며 Linux에서는 교차 컴파일만 확인했으므로 Linux 실행 성공으로 보고하지 않는다. 후속 병합·push와 원격 실행 결과는 해당 커밋의 GitHub Actions 기록으로 확인한다. 물리 전원 장애는 보류 상태를 유지한다.

## Context and Orientation

기준은 master 93c3266이며 codex/ci-automation에서 작업한다. scripts/go는 .go-version과 .tools의 Go를 사용하고 캐시는 .cache로 한정한다. 기존 테스트는 loopback 소켓과 실제 임시 APFS 파일, 자식 프로세스 종료/복구를 포함한다. 실행은 데이터와 별도인 var/ci의 새 디렉터리를 사용한다.

## Validation and Acceptance

- bash scripts/ci.sh portable: cgo=0 전체 테스트, 지원 불가 저장 동작과 format/vet/build 통과.
- bash scripts/ci.sh native: macOS arm64/APFS probe와 전체 race 테스트, 필수 통합 테스트 실행 확인.
- 잘린 JSON·빈 결과·실패·누락·예상 밖 skip·잘못된 mode가 성공으로 끝나지 않음.
- workflow 문법/표현식과 shell 문법 검사, Markdown 링크·공백 검사.
- GitHub runner에서 실제 실행은 push 이후 별도 확인 대상이며 로컬 결과로 대체하지 않는다.

2026-10-30 실제 결과:

- macOS arm64/APFS, Go 1.27.3에서 `bash scripts/ci.sh portable` 통과: 17개 패키지의 일반 Test 함수 180개 pass, skip 0. `var/ci/portable.F7LpH8`에 결과 보존. 뒤에 추가한 APFS 사전 검사에 대해서는 `CGO_ENABLED=0 scripts/go test -count=1 ./tools/storageprobe` 재검증 통과.
- 같은 호스트에서 `bash scripts/ci.sh native` 통과: APFS 확인·file/directory F_FULLFSYNC·잠금 probe, format/vet/build, 전체 race 검사. 일반 Test 함수 212개 pass, 알려진 자식 helper skip 1개는 pass에서 제외. `var/ci/native.pfZPVT`에 결과 보존. buildinfo/durable은 테스트 파일이 없어 테스트 통과 패키지로 세지 않는다.
- 결과 검사기 단위 테스트: 누락/미완료/실패/skip/부분 JSON/잘못된 manifest·모드 증거를 거절했다. 실제 portable 결과를 `-mode native`로 읽는 CLI도 missing native coverage와 exit 1로 거절했다.
- `GOOS=linux GOARCH=amd64 CGO_ENABLED=0 scripts/go test -mod=readonly -c -o <출력 디렉터리>/ ./...`로 Linux 테스트 바이너리를 교차 컴파일했다. 출력은 `var/ci/linux-compile.A6EWQx`이며 실행하지 않았다.
- 공식 actionlint v1.7.12 darwin/arm64 릴리스 SHA-256을 검증한 뒤 workflow 문법·표현식 검사 통과. `bash -n scripts/ci.sh`와 Markdown 링크/공백 검사 통과. Actions v7의 각 태그 commit과 실제 action.yml 입력도 조회했다.

## Idempotence and Recovery

검사마다 var/ci 아래 새 폴더를 만들고 이전 로그를 보존한다. 테스트 소유 임시 파일/프로세스만 조작하며 실제 거래 데이터·OS 전원은 조작하지 않는다. workflow는 저장소 쓰기 권한과 secret을 요구하지 않는다.
