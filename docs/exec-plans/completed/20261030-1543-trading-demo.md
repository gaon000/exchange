## Purpose / Big Picture

`sh scripts/demo.sh` 한 번으로 새 모의 실험을 준비하고 주문·부분 체결·잔량 취소·잔고·정상 재시작·복구를 확인한다. HTTP를 통해 실제 exchange 자식 프로세스와 통신하며, 기대값 불일치나 실행/종료 실패는 nonzero로 종료한다. 기존 run을 재사용하지 않고 결과와 실패 증거를 보존한다. 실제 전원 장애 시험은 보류한다.

## Surprises & Discoveries

- 최초 주문 응답은 OPEN을 유지하지만 현재 주문은 부분 체결 후 CANCELLED가 된다. 재시작 후 POST 재시도 전에 GET으로 최초 결과를 확인해야 유실을 새 실행으로 숨기지 않는다.
- 기존 server CLI는 port 0의 실제 주소와 복구 순번을 ready JSON으로 제공한다. 고정 포트나 외부 서버 접속이 필요 없다.
- race 계측된 테스트 자식은 종료 시 약 1초를 기다려 100ms 종료 제한에서 실패했다. 정상 종료를 검사하는 테스트의 제한을 3초로 수정했고 전체 native race 검사를 통과했다. 실제 데모의 종료 제한은 10초다.

## Outcomes & Retrospective

`sh scripts/demo.sh`로 실제 서버 초기화·주문·부분 체결·잔량 취소·잔고·정상 재시작/WAL 복구·중복 재시도를 자동 검증한다. 각 실행은 독립된 폴더에 설정·동일 서버 바이너리·HTTP 원본·프로세스 로그·요약을 보존한다. 기대값 불일치, HTTP/출력 오류와 중단 시 실패하며 자식 프로세스를 정리한다. 사용법은 [거래 데모](../../trading-demo.md)에 기록했다.

2026-10-30 macOS arm64/APFS/cgo 환경에서 실제 한 명령 실행 2회와 일반 185개·native race 217개 테스트를 통과했다. 구현·검증 요청 범위를 완료했으며 master 병합·push와 이 변경의 원격 CI 실행은 수행하지 않았다. 정상 종료 재시작을 실제 전원 장애나 강제 프로세스 종료 시험으로 보고하지 않는다. 기존 v1 계획의 전원 장애 검증 보류는 유지한다.

## Context and Orientation

기준 master는 ba4e81b다. exchange init/serve, /v1/orders·cancellations·balances·book·trades·results를 사용한다. 가격 6,000,000 ticks는 BTC당 60,000 USDT, 100 lots는 0.01 BTC다. Alice 초기 100,000 USDT/0 BTC, Bob 초기 0 USDT/1 BTC이며 세 명령 후 Alice 99,760 USDT/0.004 BTC, Bob 240 USDT/0.996 BTC, 예약 잔고는 모두 0이어야 한다.

## Plan of Work

1. scripts/demo.sh에서 기존 toolchain 설치·전용 binary 빌드 후 demo CLI를 실행한다.
2. 새 폴더와 설정·서버 binary 사본을 만들고 init/serve를 자식으로 실행한다.
3. 단계마다 독립 계산한 주문/잔고/호가/체결 결과와 HTTP 응답을 대조한다.
4. 서버 정상 종료를 확인하고 동일 run을 복구해 모든 조회와 최초 결과 bytes를 대조한다. 중복 POST 후 seq=3과 잔고가 유지되어야 한다.
5. 오류·timeout·SIGINT/SIGTERM에서 소유 자식만 종료·합류하고 로그/결과를 남긴다.

## Idempotence and Recovery

매 실행은 var/demos 아래 고유 폴더를 만든다. --output은 기존 parent 아래 새 경로만 허용한다. 중간 실패/중단 시에도 run과 HTTP/프로세스 로그를 보존하고 이미 존재하는 경로를 덮어쓰거나 삭제하지 않는다. 자식 PID 이외에는 signal을 보내지 않는다.
