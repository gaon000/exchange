## 한계와 후속 판단

비격리 개발 호스트의 warm-cache 상태·고정 초기 자금·두 가격 단계·snapshot tail 0 조건이다. 각 5회 범위를 모두 제시했고 좋은 표본만 선택하지 않았다. cold-cache·큰 WAL tail·가격 단계/계정 수 증가·장시간 HTTP 부하·현재 master의 최대 지속 처리량은 측정하지 않았다. 프로세스 memory pressure/자연 GC와 scheduler·I/O 대기는 public wall 시간에 포함되고 측정 사이 강제 GC는 제외된다.

이번 자료는 어떤 상태/단계부터 프로파일링할지 고르는 근거다. 다음 최적화 후보를 선택한다면 snapshot load/decode 및 encode/write의 추가 프로파일을 먼저 확인하고 동일 상태 5쌍과 복구 계약을 유지해 비교한다. 수치 증가만으로 생산 코드 변경이나 저장 sync 완화를 정당화하지 않는다.

**실제 OS·전원 장애 검증은 미완료·보류**다. 같은 디스크의 새 프로세스·정상 복구/bytes 일치와 물리 장애 보장을 구분한다. v1 전체 계획은 계속 Blocked다.
