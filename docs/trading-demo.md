# 한 명령 거래 데모

지원 환경은 macOS arm64·로컬 APFS·cgo다. 저장소 루트에서 실행한다.

```sh
sh scripts/demo.sh
```

스크립트는 고정 Go 도구를 준비하고 서버와 데모 CLI를 빌드한 뒤 실제 HTTP 거래를 수행한다. Go가 이미 설치되어 있으면 다시 내려받지 않는다. C compiler 등 기본 환경은 [개발 기준](development.md)을 따른다. 추가 패키지·jq·Python 설치는 필요 없다.

매번 `var/demos/demo-<고유값>/`에 새 실험을 만든다. 서버는 `127.0.0.1`의 빈 포트를 받아 실행하고 검증이 끝나면 종료한다. 기존 실험이나 실행 중인 서버에 접속하지 않는다. 모든 수치는 모의 거래의 고정 예시다.

## 확인하는 거래

| 단계 | 동작 | 자동으로 확인하는 결과 |
| --- | --- | --- |
| 초기화 | Alice에 100,000 USDT, Bob에 1 BTC 지급 | 초기 잔고·예약 0, 빈 호가·체결 |
| 매수 주문 | Alice가 60,000 USDT/BTC에 0.01 BTC 매수 | OPEN, 600 USDT 예약, 매수 호가 등록 |
| 부분 체결 | Bob이 59,900 USDT/BTC에 0.004 BTC 매도 | 먼저 대기한 매수 가격 60,000에 체결. Alice는 0.006 BTC 잔량·360 USDT 예약, Bob은 FILLED |
| 잔량 취소 | Alice의 남은 0.006 BTC 취소 | CANCELLED, 360 USDT 예약 해제, 빈 호가 |
| 잔고 확인 | 두 계정 조회 | 아래 최종 값과 일치, 예약 잔고 모두 0 |
| 정상 재시작 | SIGTERM 종료 완료 후 같은 데이터로 serve | 같은 runId, WAL 명령 3개 복구, 주문·잔고·호가·체결·최초 결과 유지 |
| 중복 재시도 | 같은 주문·취소 ID와 내용으로 세 요청 재전송 | 최초 응답 bytes 동일, 명령 순번 3·체결 수·잔고 유지 |

| 계정 | 최종 BTC | 최종 USDT | 예약 |
| --- | --- | --- | --- |
| Alice | 0.004 | 99,760 | 모두 0 |
| Bob | 0.996 | 240 | 모두 0 |

내부 검사에는 정수 lots/atoms를 사용한다. 표시값과 단위 환산은 [API 계약](design-docs/api-v1.md#1-정수-단위와-한도)에 따른다. 기대값을 거래 엔진으로 다시 계산하지 않고 명시적인 정수 결과와 대조한다.

Alice의 **최초 주문 응답은 OPEN**, 최종 **현재 주문 상태는 CANCELLED**다. 둘을 별도로 검사한다. 재시작 직후에는 변경 요청보다 먼저 GET으로 복구 상태와 최초 결과를 확인하여, 유실된 요청을 POST 재시도로 다시 실행해 복구 성공처럼 보이는 일을 막는다. 고유 명령 한도는 3으로 설정하므로 한도에 도달한 뒤에도 기존 결과를 재조회·재시도할 수 있음을 확인한다.

## 출력과 보존 파일

각 단계가 통과하면 `[확인]` 줄을 출력하고, 두 번째 서버까지 종료한 뒤 `PASS: 거래·정상 재시작·복구 확인 완료`와 결과 경로를 출력한다. 실패·응답 불일치·중단·출력/저장 오류는 종료 코드 1이다.

| 파일 | 내용 |
| --- | --- |
| `summary.json` | PASSED/FAILED, runId, 마지막 단계, 확인 항목, 오류, 서버 SHA-256, powerLossTested=false |
| `http.jsonl` | 순서대로 보낸 요청·계정·HTTP 상태·원본 응답·전송 오류. 응답은 JSON 문자열로 보존 |
| `config.json`, `exchange` | 초기 설정과 init/재시작에 공통으로 사용한 서버 바이너리 사본 |
| `init.json`, `init.stderr` | 초기화 결과·오류 |
| `server-1.json`, `server-2.json`과 각각의 `.stderr` | 첫 기동·재시작의 ready/복구 보고서와 오류 |
| `run/` | Genesis와 WAL 등 실제 모의 거래 데이터 |

실패하더라도 생성한 폴더는 보존한다. 기본값으로 다시 실행하면 새 폴더를 사용한다. `--output`으로 직접 지정할 때는 기존 parent 아래 **아직 없는 경로**를 사용한다. 빈 디렉터리도 재사용하지 않는다.

```sh
sh scripts/demo.sh --output var/my-trading-demo
```

이미 빌드했다면 `bin/demo --exchange bin/demo-exchange`로도 실행할 수 있다. `bin/demo -h`에서 옵션을 확인한다. 기본 전체 실행 제한은 빌드 이후 2분이며 `--timeout`으로 10분 이내에서 변경한다. 각 HTTP 요청은 5초, 서버 준비는 10초 제한이다. 중단/실패 시 자기 자식에게만 SIGTERM을 보내고 최대 10초 뒤에도 끝나지 않으면 해당 자식을 종료하고 실패로 기록한다. 정리 시간은 전체 실행 제한에 더해질 수 있다.

이 데모는 **정상 종료 후 WAL 재생**을 검증한다. 스냅샷 복구·강제 종료·실제 전원 장애·성능 측정의 증거로 사용하지 않는다. 전원 장애 검증은 보류 상태다.

## 자동 검사 연결

[native 테스트](../cmd/demo/native_test.go)는 실제 서버를 빌드해 성공·부분 체결 직후 취소/출력 오류·기존 결과 보존을 검사한다. 종료 뒤 run 잠금과 포트가 해제되고, 복구 결과 GET이 재시도 POST보다 먼저 수행됐는지 확인한다. [일반 테스트](../cmd/demo/command_test.go)는 잘못된 잔고·업무 거절·HTTP 오류·redirect·잘린/큰 응답·기록 실패와 자식 시작/종료 실패를 검사한다. [미지원 환경 테스트](../cmd/demo/unsupported_test.go)는 새 결과 폴더를 만들지 않고 거절하는지 확인한다.

두 CI job에서 관련 시험을 실행하며 [필수 실행 검사](../tools/civerify/main.go)에도 연결한다. 실제 원격 실행 결과는 해당 커밋의 Actions 기록으로 확인한다.
